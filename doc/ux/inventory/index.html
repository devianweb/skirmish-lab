SkirmishLab UI inventory

Every screen, panel and prompt in the game as of the 14C-2 PR 9 build (master, 11 Nov 2026), with what each one is and what it is for. Use it as the starting point for the 14G design pass.

Screenshots come from a headless browser at 1600 × 900. In-match shots run the real HUD and engine on one page with scripted dice, so a prompt can be shown from both seats. Lobby shots use two real browsers over the signaling server. Click a screenshot to enlarge it. Open this file directly in a browser; it needs no server.

58 screenshots · 10 sections · not shown: the dangerous-terrain casualty selector on a squad move and the "jump N dice" chip (described in the movement section)

Design observations

  1. Dice panel. During setup the Dice panel shows an empty attack template ("Attacker → target", "To-Hit (need Q4+)", "0 hits · 0 blocked · 0 wounds") because the latest roll (objective count, roll-offs) is not an attack. See the objective screenshots.
  2. Log wording. Some log lines print the raw action name: "Host concede", "Guest request-rematch", "Host held with …" for an idle Shaken unit.
  3. Header colours. The turn label shows "Defeat" in the same green as "Your turn", and "Victory" in orange.
  4. Confirm summaries. Multi-weapon and charge confirmations are 4 to 5 lines of dense text in one paragraph (weapons, dice, target numbers, pile-in, step-back). A structured layout (one row per weapon, icons for Q/D) would scan faster.
  5. Bottom of the screen. The data card and the action/prompt bar are two separate floating panels stacked at the bottom; together they cover a large part of the board, and the red keep-away legend banner overlaps the data card.
  6. Roster panel. Both sides share one tall scrolling panel; the enemy list usually falls below the fold. Friendly cards are large, enemy cards are compact one-liners. Status tags (UNDEPLOYED, ACTIVATED, SHAKEN, FATIGUED, ENGAGED, IN RESERVE (AMBUSH), HELD AS SCOUT) are all small coloured text, so Shaken does not stand out.
  7. Top-centre slot. Toasts, the setup panel, the terrain-debugger pill and rejection banners all appear in the same spot under the header and can stack on each other.
  8. Icons. Emoji act as icons in some prompts (📍 placement, ⚠️ alerts, 🎯 objectives, ⏳ waiting) while the rest of the HUD is text-only.
  9. Reaction docks. The docks share a pattern (title, countdown, description, buttons), but button order and colours differ: Push = Auto (green) / Confirm / Don't push (red); Pile in = Auto place / Confirm (green) / Reset; Casualties = Auto pick / Confirm.
  10. Board scale. The default camera frames the whole 48" board, so units are small and the action often sits far from the camera. A focus-on-selection camera or zoom shortcut would help.
  11. Lobby. The guest has no army choice (the host picks both; already a 14G item). The deployment checkbox reads "Interactive Pre-Match Deployment (12" Zones)" and without it a game skips deployment but still places objectives.
  12. Map Builder. The top toolbar is crowded with two-line button labels; the status pill (Ready / Notice) looks like a button.
  13. Match end. The results modal sits over the live HUD; the roster, Dice/Log and data card stay visible behind it.
  14. Setup header. During setup the header still shows the objective score (Host 0 — Guest 0), and the "Round N started" toast fires before the Ambush step of that round.

Lobby and Map Builder

What a player sees before a match starts.

01

Lobby

What it is
Centred card with the SkirmishLab title, a "Battlefield & Forces" box (map, Host force, Guest force, deployment checkbox), Create Room, the invite-code field with Join Room, Map Builder, and the fan-project disclaimer with the link to the free rules.
Purpose
The only entry point. The host picks the map and both armies here, then creates a room; the guest types the XXX-XXX code and joins.

02

Lobby, developer mode

What it is
Same card with a yellow DEV badge top right and a "Developer mode on" pill at the bottom. F9 toggles it.
Purpose
Unlocks the TEST armies (and the dev maps) in the army lists for hand testing.

03

Waiting room (host)

What it is
Card with the room code, the role (HOST), the chosen map and "Waiting for peer…".
Purpose
Shows the host the code to share while the signaling server waits for the guest.

04

Join (guest)

What it is
The lobby with an invite code typed into the code field.
Purpose
How the guest enters a room. The guest currently has no army picker of their own (14G item: each player picks their own army).

05

Map Builder

What it is
Full-screen board with a top toolbar (map name, Snap 1.0" / 0.5" / Free, board size, Load Map, status pill, Import JSON, Export JSON, Auto Obj, Clear, Save Map, Exit) and a bottom palette with category tabs (Structures, Walls & Doors, Platforms & Decks, Stairs & Ladders, Cover & Pipes, Area Terrain, Objectives), piece cards and a keyboard-shortcut strip.
Purpose
Build and save custom maps that the host can pick in the lobby. Auto Obj and the Objectives tab are removed by 14C-2 PR 9 (players place objectives in the match now).

06

Map Builder, piece selected in the palette

What it is
A palette card highlighted in blue; the next click on the board places that piece.
Purpose
Placing terrain. A placed piece opens an inspector (nudge X/Z, rotate, duplicate, raise/lower, delete), not captured here.

The game screen

The layout every in-match screenshot below shares.

07

Game screen at rest

What it is
Header bar (SkirmishLab, round badge "Round 1 / 4", objective score Host 0 — Guest 0, turn label "Your turn", room code, Concede). Left: the roster panel, your units first ("HOST — FIGHTERS (8 READY)") then the enemy's. Right: the Dice panel (latest roll) above the Log (newest first). Bottom centre: the status bar ("Your turn — activate a unit (8 available)"). Behind everything: the 3D board.
Purpose
Home base of a match. Everything else is a state of these five areas: header, roster, dice/log, bottom dock, board markers.

08

Unit data card (hover)

What it is
A wide card above the bottom bar: name, Friendly/Enemy and side colour, type, model count, special rules, a status pill (READY / ACTIVATED / SHAKEN / FATIGUED / ENGAGED) and a stat row (Quality, Defense, Tough, Models, Move, Charge) with a weapons table (Weapon, Type, Range, Dice, Traits).
Purpose
Read any unit's profile by hovering it on the board or in the roster. It stays up while you act with the active unit.

Objectives and deployment

Pre-game phases (objectives phase from 14C-2 PR 8/9).

09

Place an objective

What it is
Setup panel at the top centre with the objective roll ("Objective roll: 6 — 5 objectives"), the mission roll-off result and its dice pairs. Both deployment zones are shaded; a ring follows the cursor (green = legal). Bottom bar: "Place objective 1 of 5 — click the board outside both deployment zones, more than 9" from other objectives".
Purpose
The roll-off winner and then the other player alternate placing the rolled number of markers.

10

Illegal objective spot

What it is
The 9" circle around a placed marker, the cursor ring turned red, and the reason under the prompt ("Objective must be more than 9" from every other objective").
Purpose
Explains why a spot is refused before the click.

11

Objective confirm

What it is
The normal Confirm / Cancel bar for the staged marker.
Purpose
Same commit pattern as every other action.

12

Waiting for the other player

What it is
Bottom bar "Waiting for Guest to place objective 2 of 5"; the header reads "Guest's turn to place an objective".
Purpose
The non-placing player watches.

13

Deployment

What it is
The setup panel now adds the deployment roll-off ("Host deploys first … Host also activates first in round 1"). The next undeployed unit is highlighted in the roster (UNDEPLOYED, SCOUT and IN RESERVE (AMBUSH) tags), the zones are tinted, an objective card is up (control radius, presence, how control works), and the bar says "Deploying Test Line Troops 1 — click any legal position within your 12" deployment zone".
Purpose
Players alternate placing one unit at a time inside their own zone.

14

Deploy confirm

What it is
Confirm / Cancel for the placed unit.
Purpose
Commit the deployment spot.

15

Scout choice

What it is
For a Scout unit the bar adds "Deploy now" and "Hold as Scout".
Purpose
A Scout may deploy normally or wait and deploy after everyone else, further forward.

16

Scout stage

What it is
Held Scouts show HELD AS SCOUT; the wider Scout zone is shaded and the bar reads "Placing Scout … click within 9" of your deployment zone and more than 9" from enemy units that aren't Scouts".
Purpose
Places the held Scouts, alternating, after normal deployment.

17

Ambush step (round 2+)

What it is
Header "Your turn to place Ambush units", orange circles marking ground within 9" of enemy models, the reserve units highlighted, the reason for a refused spot ("Cannot deploy inside a terrain obstacle") and "Skip (wait for a later round)".
Purpose
Before the first activation of rounds 2 to 4 players alternate bringing in Ambush units, or wait.

18

Skip Ambush confirm

What it is
"Skip placing Ambush units this round (they wait for a later round)" with Confirm / Cancel.
Purpose
Skipping is a real choice, so it is confirmed like any action.

Activating a unit

Picking a unit and choosing its action.

19

Activation confirm

What it is
Clicking one of your ready units selects it (blue rings on its models), shows its data card, and asks "Activate Test Impact Brutes 3" with Confirm / Cancel.
Purpose
Commits the unit for this activation (it cannot be undone). Dangerous terrain under the unit rolls at this point.

20

Action bar

What it is
The active unit's name followed by Advance, Rush, Shoot, Charge and Hold (Hold becomes End Activation once the unit has acted). Unavailable actions are greyed. The roster card shows ACTIVATED and a dot.
Purpose
The one place to choose what the unit does this activation.

21

Shaken unit

What it is
A Shaken unit's roster card shows SHAKEN; activating it offers only "End activation with … (idle: clears Shaken)".
Purpose
Enforces the v3.6 rule that a Shaken unit spends its activation idle to recover.

Movement

Advance, Rush and the move preview.

22

Advance preview

What it is
Yellow ring = the move allowance around the model being placed; a path line to the cursor; red rings = the 1" keep-away zones around other units. Bottom: "Select model" chips (Model 1/2/3) and "Place Model 1 of 3 (…) within 6"".
Purpose
Shows exactly where the selected model can go before you commit.

23

Squad placement

What it is
After placing one model, its chip turns green (✓ Model 1), the next chip is selected, and cyan rings show where the other models will follow. Buttons: Confirm move, Reset Placement, Cancel.
Purpose
Place one model and Confirm, and the rest follow in formation (or place each by hand).

24

Move confirm summary

What it is
One-line summary ("Advance Test Impact Brutes 3 (3 models) · can shoot after moving") with Confirm / Cancel, and the red keep-away legend banner above the data card.
Purpose
Last check before the host validates and applies the move.

25

After moving

What it is
The unit at its new spot; the log gains "Host advanced …"; Rush and Charge are now greyed and Hold has become End Activation.
Purpose
Shows what is still allowed after an Advance (shooting).

26

Traversal chip and stop note

What it is
A small chip on the path ("gap 0.6"") and a labelled stop note ("Stopped: blocked by terrain") on the board and in the bottom bar.
Purpose
Explains climbs, drops, gaps and jumps (with their dice) and why a path ends short of the cursor.

27

Flying unit

What it is
A Flying unit's data card tag and its move preview (straight path over terrain; the Flying chip and dashed cyan line appear on the path).
Purpose
Flying ignores terrain and units along the way; only the stop spot is checked.

28

Follower that cannot follow

What it is
The chip of a model that could not follow turns red (✗ Model 2), the bar explains why ("Squad model spread of 10.60" exceeds max coherency limit of 6". Place it by hand") and a yellow toast repeats it at the top.
Purpose
Tells the player which model needs placing by hand.

29

Rejected action toast

What it is
A yellow banner under the header: "Action rejected: Squad model 2: Models cannot end movement partly overhanging an edge — the whole base must rest on the floor".
Purpose
The host refused the action; the HUD returns to the action bar with the reason.

Shooting

Targeting, weapon allocation and results.

30

Shoot targeting

What it is
Red range fan with line-of-sight shading around the shooter, aim lines from each firing model to the hovered enemy, the enemy's data card, a chip "3 of 3 models can fire (Assault Rifle)" and the hint "Select an enemy target within the red range ring (shoot)".
Purpose
Shows who can fire at what before you pick a target.

31

Shoot confirm

What it is
Summary "Test Assault Troops 7 fires Assault Rifle at Test Squad A 2 (8.0") · Assault Rifle: 6d6 (Hit Q4+, Def D5+)" with Confirm / Cancel.
Purpose
Dice count and target numbers before rolling.

32

Dice panel after a shot

What it is
Dice panel: "Attacker → Target", To-Hit dice (green hits, grey misses), Defense dice (red unblocked), and a line "0 hits · 0 blocked · 0 wounds". The log gains "Host shot Test Squad A 2".
Purpose
Every roll is shown to both players from the shared state.

33

Multi-weapon unit

What it is
One chip per ranged weapon ("Frag Launcher (24") ➔ Unassigned", …) and the hint "Click an enemy target to assign all weapons, or click a weapon chip to target independently".
Purpose
Units with several weapons can split fire (max two targets; same-named weapons together).

34

Split fire

What it is
Chips show each weapon's target; the summary lists every weapon with dice and target numbers.
Purpose
Review the full allocation before Confirm.

35

Salvo result with Blast

What it is
Dice panel "… Salvo (5 weapons)": one block per weapon, a total line, the Blast spread line and the "Blast spill" note. Bottom: "Waiting for Host to remove casualties (29s)…".
Purpose
Multi-weapon and Blast results; the opponent is now picking casualties.

Charge and melee

Charge declaration, legs, reactions and results.

36

Charge targeting

What it is
Red 12" charge range and the hint "Click an enemy unit within charge range to Charge into melee and strike".
Purpose
Pick the unit to charge.

37

Declare charge

What it is
A long explanation (place each model into base contact, can't be undone, Abandon ends the activation) with Confirm / Cancel.
Purpose
Declaring locks the unit into the charge.

38

Charge legs

What it is
Model chips, the 12" allowance ring, keep-away rings (the target's in green), and the instruction "Charge on Test Squad A 2: place Model 1 of 3 (12.0" left)…". Abandon charge replaces Cancel.
Purpose
Move the chargers into contact, one leg at a time if needed.

39

Charge confirm

What it is
Summary of the walk, who strikes ("3 of 3 models within 3" strike (6 attacks)"), what the defenders will do (pile in up to 3", retaliate) and the step-back.
Purpose
Final check before the host resolves the charge.

40

Waiting for the defender

What it is
The attacker's bottom bar: "Waiting for Guest to pile in (58s)…".
Purpose
Every reaction the opponent owns shows a waiting bar with its countdown.

41

Pile-in dock (defender)

What it is
Title "PILE IN" with the countdown, the explanation, model chips for models not yet in contact, and Auto place / Confirm / Reset.
Purpose
The defender moves models not in contact up to 3" before the strike.

42

Remove casualties

What it is
Title "REMOVE 2 MODELS FROM TEST SQUAD A 2" with countdown, the rule text, one button per model (with wounds, and "splits the squad" where relevant), and Auto pick / Confirm.
Purpose
The owner picks which models die (timeout = host auto pick).

43

Casualties being picked

What it is
Picked models turn orange (✕ Model 4) on the chips and get an orange ring on the board; the counter reads (1/2).
Purpose
Visual check of the pick before Confirm.

44

Strike back prompt

What it is
Title "MELEE RETALIATION" with countdown, "Test Impact Brutes 3 charged Test Squad A 2! Strike back with Blade?", a red Fatigue warning, and Strike Back (Blade) / Decline (Avoid Fatigue).
Purpose
The charged unit chooses whether to strike back.

45

Victory consolidation

What it is
Title "VICTORY CONSOLIDATION": the target was wiped out, move up to 3" or Stay Put.
Purpose
The winner of a melee that destroyed the other unit may move 3".

46

Melee result and Morale

What it is
Dice panel titled "Melee result & Morale": the melee line (each side's wounds) and the Morale die with its outcome (Shaken). The log entry for "Host ended an activation" carries the same lines indented.
Purpose
End-of-activation results. From PR 8 the lines name each unit's owner and spell out Fear.

Push

After an attack makes a unit Shaken.

47

Push prompt (attacker)

What it is
Title "PUSH" with countdown, "Test Squad A 2 is Shaken: move one of its models up to 2". Auto pushes the model nearest …", and Auto / Confirm / Don't push.
Purpose
The attacker may push one model 2" (Don't push is the one agreed third button).

48

Push placement

What it is
Model chips for the Shaken unit, the 2" ring on the highlighted model, keep-away rings, and Push / Back / Don't push.
Purpose
Pick the model and the spot to push it to.

49

Push, defender view

What it is
The Shaken unit's owner sees the waiting bar.
Purpose
Same waiting pattern as other reactions.

Alerts, toasts and debug

Connection state and tools.

50

Opponent disconnected

What it is
Full-width red banner under the header: "Opponent disconnected — waiting for peer to reconnect… (Grace period: 5m)".
Purpose
Tells the player the game is paused for a reconnect.

51

Signaling reconnecting

What it is
Amber banner "Signaling disconnected — reconnecting to room…".
Purpose
The dice/signaling server dropped; play resumes when it is back.

52

Toast

What it is
Small banner under the header ("Action rejected: Move exceeds unit speed").
Purpose
Short-lived feedback (rejections, round start, hints).

53

Terrain debugger (F9 in game)

What it is
A pill "Terrain debugger: ON (hover terrain to inspect, F9 to hide)", wireframe collision volumes for units and terrain, and an inspector card for the hovered piece (id, type, LoS/cover flags, position, scale, rotation, footprint, half-extents).
Purpose
Developer view for checking collision, cover and line of sight.

Concede and match end

Leaving or finishing a match.

54

Concede dialog

What it is
Small modal "Concede the match? You lose and your opponent wins." with Concede (red) / Cancel.
Purpose
Guards the Concede button in the header.

55

Results: Defeat

What it is
Modal with the title (Defeat), the reason ("Host conceded"), rounds played, final objective score, units/models lost per side, and Play Again / Return to Lobby.
Purpose
Match result for each player.

56

Results: Victory

What it is
Same modal for the winner.
Purpose
Match result.

57

Rematch requested

What it is
Play Again becomes a disabled "Waiting for Host…".
Purpose
Both players must agree to a rematch.

58

Rematch offered

What it is
The other player sees "Guest wants a rematch" and an Accept rematch button.
Purpose
Accepting restarts the same game (same map, armies, sides, objectives).
